100% 브라우저 로컬 데이터 처리와 보안 우수성

최종 갱신: 2026년 8월 24일 읽는 시간: 약 6분 기술: File System API, Web Worker

전통적인 웹 유틸리티 사이트(온라인 PDF 변환기, 음원 인코더, 이미지 압축기 등)는 사용자가 업로드한 파일을 자사 클라우드 서버로 전송받아 가공한 뒤 다시 내려주는 방식을 취해 왔습니다. 하지만 이 과정에서 기업 기밀, 개인 음성 데이터, 미발표 디자인 에셋이 외부 서버에 노출되거나 임시 저장되는 중대한 보안 취약점이 발생합니다.

서버리스 클라이언트 아키텍처: 배처 툴(Batcher Tools)은 모든 파일 디코딩, 리사이징, 이름 변경, 인코딩 작업을 사용자의 웹 브라우저 메모리 안에서 단독 실행합니다. 네트워크를 통한 외부 유출이 0바이트인 제로 트러스트(Zero Trust) 환경을 제공합니다.

1. 브라우저 로컬 구동을 가능케 하는 3대 핵심 기술

1) WICG File System Access API

크롬, 엣지 등 최신 브라우저가 지원하는 파일 시스템 액세스 API를 통해 사용자가 명시적으로 승인한 로컬 폴더의 파일 핸들을 안전하게 읽고, 별도의 ZIP 다운로드 없이 변경 사항을 원본 디렉토리에 직접 저장할 수 있습니다.

2) HTML5 Canvas 2D & WebGL 가속

SVG 벡터 데이터를 로컬 GPU 가속을 받는 오프스크린 캔버스에 렌더링한 후, 무손실 32비트 PNG 바이너리 블롭(Blob)으로 즉시 변환합니다.

3) Web Worker 기반 멀티스레드 인코딩

대용량 오디오 인코딩 연산을 메인 UI 스레드가 아닌 백그라운드 워커 스레드로 분산하여, 수백 개의 파일을 변환하는 동안에도 브라우저 화면이 멈추지 않고 매끄럽게 동작합니다.

2. 서버 전송 방식 vs 브라우저 로컬 방식 비교

비교 항목 기존 서버 업로드 방식 배처 툴 (로컬 브라우저)
데이터 보안성 서버 유출 및 보관 리스크 존재 100% 완전한 로컬 격리 (유출 불가능)
네트워크 대역폭 파일 업로드/다운로드 트래픽 소모 0 MB (네트워크 트래픽 없음)
오프라인 지원 인터넷 끊기면 작동 불가 인터넷 없어도 오프라인 구동 가능
파일 용량 제한 서버 업로드 한도(예: 50MB) 존재 내 PC 램(RAM) 한도만큼 무제한
